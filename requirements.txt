# Python dependencies for the data pipeline (`scripts/`).
#
# Pinned EXACTLY, and that is the point of the file. Both workflows used to
# `pip install <bare names>`, so every morning re-resolved the latest release of
# everything — production changed without a commit.
#
# Read the reach literally: these are the DIRECT dependencies. Observed
# 2026-08-23 on Python 3.12 (the version CI uses), the resolved environment was
# 29 packages of which 9 are named here and in requirements-dev.txt — so 20
# transitive ones (httpcore, pydantic, certifi, soupsieve, jiter …) still
# re-resolve on every run. Those counts are a measurement, not a constant: they
# move on their own, because nothing pins them. That is the point. So "production cannot change without a commit" is NOT
# true yet — a breaking release of a transitive dependency reaches the morning
# exactly the way #80 did. What this file removes is the specific class that bit
# us: a library this repo imports itself, changing major under us. #93 tracks
# locking the whole closure. On 2026-08-20 `anthropic`
# 1.0.0 did exactly that: it moved the HTTP layer to the `httpx2` fork, `httpx`
# stopped being installed, and `summarizer.sync_call_kwargs` (which imports
# `httpx` directly) took every meeting down for three mornings. See #80.
#
# The versions here are not chosen, they are OBSERVED: each one is what the last
# green run of daily-batch.yml / ci.yml actually installed, so adopting this file
# changed nothing about what runs. Bump them in a commit, with the test suite as
# the evidence — that commit is the thing whose absence caused the outage.
#
# `httpx` is listed even though `anthropic` 0.x installs it anyway (#81): a
# library we `import` ourselves is ours to declare. Leaving it implicit is what
# let someone else's dependency change break our import.
